# Project-Dog 项目指南

## 1. 先认识这个项目

当前交接包主要是**单腿台架的电机控制与跳跃测试代码**，不是完整的四足机器人控制系统。它有两条相对独立的线：

- <span style="color: #2f9e44">C/C++ 程序连接 EtherCAT 从站</span>，<span style="color: #2f9e44">通过从站中的 CAN 通道与三个电机通信</span>，<span style="color: #2f9e44">用来读角度、站立和测试跳跃</span>。
- `tools/dog_leg_kinematics.py` 在电脑上<span style="color: #2f9e44">离线计算左前腿的足端位置和电机角度</span>。它不连接电机，也没有被 C++ 控制程序调用。

现有测试记录显示，屈膝测试的第 1、2 组已通过；跳跃有试跳和 10 次试跑记录，但测试计划中的正式跳跃组仍标为未测试。

## 2. 文件放在哪里

```text
Project-Dog_交接包/
├── Project-Dog/                         本项目，也是下面命令的工作目录
│   ├── CMakeLists.txt                   定义控制库与五个可执行程序
│   ├── read_angles.cpp                  读取三个电机的当前角度
│   ├── stand_position.cpp               移到站立姿态并保持
│   ├── jump_position.cpp                位置模式单次跳跃
│   ├── jump_mit.cpp                     力位混合模式单次跳跃 / 落地测试
│   ├── jump_test.cpp                    力位混合模式连续跳跃与记录
│   ├── motor_config.h                   电机 ID 与通道配置
│   ├── motor_bus.*                      指令交接、反馈查询接口
│   ├── motor_control.*                  电机协议的指令打包与反馈解码
│   ├── transmit.*、pdo_types.h          EtherCAT 收发与报文结构
│   ├── periodic_clock.h、queue.h         周期计时与命令队列
│   ├── math_ops.*                       协议编码所需的数值转换
│   ├── tools/dog_leg_kinematics.py       离线运动学模型
│   ├── pyproject.toml、uv.lock           Python 依赖声明和锁定
│   ├── 使用说明/                         测试计划、记录及配图
│   ├── 机器狗左前腿运动学模型说明.md      模型推导、标定和接口
│   └── thirdparty/soem/                 随项目附带的 EtherCAT 库
└── 补充说明文档/                         另存的说明及单腿测试 PDF
```

`补充说明文档` 中有与项目内同名的说明文件，但内容并不完全相同；查阅时留意文件位置和日期。`build/` 是配置后生成的构建目录，`logs/` 是运行跳跃测试后生成的日志目录，交接包中未必已有。

### 第三方目录怎么看

顶层 `CMakeLists.txt` 通过 `add_subdirectory(thirdparty)` 进入 `thirdparty/CMakeLists.txt`；后者只有一行 `add_subdirectory(soem)`，作用是把 SOEM 加入构建。SOEM 的 CMake 配置会生成 `soem` 库，再由项目的 `motor` 库链接。

`thirdparty/soem/soem/` <span style="color: #2f9e44">是 SOEM 的 EtherCAT 协议实现</span>；`osal/` 和 `oshw/` 分别放操作系统与硬件接口相关代码。`appveyor.yml` 是该第三方库的持续集成配置，`ChangeLog` 是它的变更记录，`ethercatprint.h` 属于 SOEM 的输出接口。第一次读项目时不必从这些文件入手，碰到 `ec_init`、`ec_send_processdata` 等具体接口再回头查即可。项目顶层 CMake 直接引用了 SOEM 的 Linux 头文件路径，实际控制环境按 Linux 准备。

## 3. 程序是怎样让腿动起来的

可以把一次控制过程想成下面这条路：

```text
动作程序：决定目标角度、速度和当前动作阶段
    ↓
motor_control：将目标打包成电机协议报文
    ↓
motor_bus / transmit：交给后台线程，按周期交换 EtherCAT PDO
    ↓
SOEM → EtherCAT 从站 → CAN 通道 → 电机
    ↑
电机反馈沿相反方向回来，解码后由 motor_bus 缓存，供动作程序读取
```

<span style="color: #2f9e44">EtherCAT 是电脑与从站之间的通信方式</span>；<span style="color: #2f9e44">PDO 可以先理解成每个周期交换的一块输入/输出数据</span>。项目的 `EtherCAT_Msg` 里有多个<span style="color: #2f9e44">电机报文槽</span>，具体结构在 `pdo_types.h`。后台线程的<span style="color: #2f9e44">目标周期为 1 ms</span>，见 `transmit.cpp` 的 `runImpl()` 和 `periodic_clock.h`；这描述的是软件调度方式，并不保证普通 Linux 上每个周期都严格准时。

动作程序调用 `startBus()`，<span style="color: #2f9e44">初始化总线并启动收发线程</span>；<span style="color: #2f9e44">查询初始位置后，生成目标报文</span>，通过 `exchangeMotorFrame()` 交给后台线程。反馈由 `RV_can_data_repack()` 解码，再由 `recordMotorFeedback()` 更新缓存，动作程序通过 `motorFeedback()` 读取。退出时调用 `stopBus()` 结束线程并关闭连接。

当前配置写在代码里：`transmit.cpp` 的 `startBus()` 使用网卡 `enp4s0`，`transmit.h` 的 `SLAVE_NUMBER` 为 1，`motor_config.h` 将 ID 1、2、3 分别映射到通道 1、2、3。更换电脑或接线后，要先核对这些配置；当前程序没有命令行网卡参数。源码中动作姿态数组按 **ID1 膝、ID2 大腿、ID3** 排列，离线模型则按 **HAA、HFE、膝** 排列，不能把两个数组直接按下标对应。

## 4. 建议怎样读代码

第一遍先跟着一条实际动作走，不必一开始就钻进通信协议。

1. **看** `motor_config.h` 和 `read_angles.cpp`。 前者回答电机和通道如何对应；后者很短，展示启动总线、逐个查询角度、退出的基本流程。它只发位置查询，不发送运动、使能、制动或调零命令。
2. **看** `stand_position.cpp`。 从 `main()` 开始，看它怎样读取起始角度、计算三个轴同步到站立姿态的时间，再循环发送位置目标。站立目标写在文件开头，完成后会一直保持到手动退出。
3. **看** `jump_mit.cpp` 的 `main()`，再回头看 `Leg`。 主函数先串起 stand、crouch、push、空中到 land、触地检测、缓冲和回站；`Leg` 中的函数再解释每段轨迹和增益如何产生。`drop` 分支单独测试落地缓冲，不执行蹬伸。
4. **看** `jump_test.cpp`。 它把类似动作放进循环，按指定质量调整部分参数，并记录每次测试。留意周期包含整套动作：若动作超出设定周期，代码不会截断动作，也不会补跑错过的周期。
5. **按需看底层。** 沿 `motor_bus.h` → `motor_bus.cpp` → `transmit.cpp` → `motor_control.c` 跟一条指令和一条反馈。`queue.h` 包含队列和查询接口；当前动作程序主要用完整帧交接，初始角度另走查询。`math_ops.c` 负责数值限幅、编码转换等辅助运算。
6. **最后看** `jump_position.cpp` 和运动学脚本。 前者是另一套位置模式单次跳跃，姿态和阶段与 `jump_mit` 不完全一样，不能混用参数；后者与在线控制分开，适合结合模型说明阅读。

`config.h` 目前只是包含 `pdo_types.h` 的薄头文件。`stage1_runtime.cpp/.h` 保留了少量停止请求代码，但没有列入当前顶层 CMake 的构建目标，也没有被上述程序调用；不要据此认为当前可执行程序提供了它的控制接口。

## 5. 编译与查看用法

在 Linux 上准备 C/C++ 编译器、CMake、Boost 头文件和线程库。SOEM 源码已包含在项目中；顶层配置要求 C++17。首次在项目目录执行：

```bash
cmake -S . -B build
cmake --build build -j
```

之后修改代码，通常重新执行 `cmake --build build -j` 即可。生成的五个程序是 `read_angles`、`stand_position`、`jump_position`、`jump_mit`、`jump_test`。不连接硬件时也可查看参数，例如：

```bash
./build/jump_mit --help
./build/jump_test --help
```

实<span style="color: #2f9e44">际运行需要连接对应的 EtherCAT 网卡和单腿台架</span>，通常使用 `sudo` 获得原始网络访问权限。先用 `ip link` 确认网卡名称与代码一致。不要同时运行多个控制程序；动作程序会实际驱动电机。根据随包测试说明，退出前应托住滑台，再按 `Ctrl+C`；如果中途异常，也按台架现场的停止流程处理。

### 各程序怎么用

| 程序 | 做什么 | 参数与结束方式 |
| --- | --- | --- |
| `read_angles` | 读取并打印 ID1、ID2、ID3 的角度 | 无参数，读完退出；查询不到时会持续重试，可按 `Ctrl+C` |
| `stand_position` | 从当前角度同步移到站立目标 | 无参数，到位后持续保持，`Ctrl+C` 退出 |
| `jump_position` | 位置模式执行一次跳跃 | 可选蹬伸速度、落地初速度，默认 340、400 deg/s；完成后保持站立 |
| `jump_mit` | <span style="color: #2f9e44">力位混合模式单次跳跃</span>；也支持 `drop` 落地测试 | 位置参数较多，先查 `--help`；完成后保持站立，退出时保存日志 |
| `jump_test` | <span style="color: #2f9e44">连续跳跃并记录测试数据</span> | 四个必填参数依次为蹬伸速度、周期、次数、总运动质量；完成后保持站立，退出时保存日志 |

例如，随包记录里的空载 10 次试跑命令是：

```bash
sudo ./build/jump_test 450 3 10 6.2
```

其中 `450` 是蹬伸速度（deg/s），`3` 是周期（秒），`10` 是次数，`6.2` 是随腿运动的总质量（kg），包括滑台和额外配重。它是已有试跑记录，不是对其他设备或负载的通用参数推荐。正式测试前应核对当前台架、配重、姿态和记录，先进行小次数试跑。程序按总质量缩放部分重力前馈和落地增益，具体公式见 `jump_test.cpp` 和测试记录。

两个跳跃程序的 CSV 写到**运行时工作目录**下的 `logs/`，所以从项目目录运行时才是 `Project-Dog/logs/`。`jump_mit` 写逐周期文件；`jump_test` 写汇总及选定跳次的逐周期文件，中途退出也会尝试保存未完成跳次的数据。记录包含指令、反馈等信息；详情看各自的 `CycleLog` / `TestLog`。`logs/` 被 `.gitignore` 忽略，需要单独归档实测数据。

随包 PDF 提到 1 秒周期时“落地后不站起来”，但当前 `jump_test.cpp` 每次都会执行回站，动作超期则顺延下一次。这里按当前源码说明；历史 PDF 和记录中的参数、命令也应先与当前版本核对。测试记录里提到的 `FlexTrial`、`TestStatus`、`TestStop` 不在当前 CMake 生成的五个程序中，不要直接当成本包可用命令。

## 6. 离线运动学怎么用

这个脚本解决的是另一类问题：<span style="color: #2f9e44">给定足端球心位置，求模型中的三个电机角；或根据电机角反算足端位置。模型使用髋坐标系，位置单位为 **mm**，角度单位为 **rad**</span>。`foot_to_motor()` 返回的 `info['ok']` 会检查是否有解以及膝机构死点余量，但不覆盖机械干涉、所有关节限位或标定误差。

项目用 `uv` 管理 Python 依赖（Python 3.8 及以上、NumPy；`.python-version` 指定 3.10）。在项目目录执行：

```bash
uv sync
uv run python tools/dog_leg_kinematics.py
```

脚本会打印零位和几组正逆解往返结果。注意项目内模型说明末尾的脚本路径少了 `tools/`；以上命令对应当前目录结构。在项目根目录编写脚本时，可这样导入并做一次计算：

```python
from tools.dog_leg_kinematics import LegModel

leg = LegModel()  # 默认方向和零点，尚未按实物标定
q, info = leg.foot_to_motor([0, 120.5, -300])
print(q, info['ok'], info['reason'])
if info['ok']:
    print(leg.motor_to_foot(q))
```

默认 `Calibration` 的方向全为正、偏移全为零，只适合模型计算。实际使用前需要按 [运动学模型说明](%E6%9C%BA%E5%99%A8%E7%8B%97%E5%B7%A6%E5%89%8D%E8%85%BF%E8%BF%90%E5%8A%A8%E5%AD%A6%E6%A8%A1%E5%9E%8B%E8%AF%B4%E6%98%8E.md) 标定方向和零点，核对坐标系、机械限位及干涉。模型没有动力学，也没有直接下发到电机的功能；`info['ok']` 为真不代表可以直接用于实机。

## 7. 要改东西时从哪里找

| 想做的事 | 先看哪里 |
| --- | --- |
| 改电机 ID、通道或网卡 | `motor_config.h`；`transmit.cpp` 的 `startBus()` |
| 改站立目标 | `stand_position.cpp` 顶部的 `target_deg`；跳跃程序各自也有独立姿态常量 |
| 调单次跳跃轨迹、触地判断或增益 | `jump_mit.cpp` 的姿态常量、`Leg` 和 `usage()` |
| 调连续测试的周期、次数、质量与日志 | `jump_test.cpp` 的 `main()`、`Leg`、`TestLog` |
| 排查设备发现、PDO 和反馈 | `transmit.cpp`、`pdo_types.h`、`motor_bus.cpp`、`motor_control.c` |
| 理解足端与关节的关系 | `tools/dog_leg_kinematics.py` 和模型说明 |

同名姿态和相似轨迹分别写在多个程序中，改一处不会自动同步其他程序。先确认要运行哪个程序，再修改并重新编译；涉及实物动作时还应更新测试记录，记录版本、参数、负载和实际结果。
